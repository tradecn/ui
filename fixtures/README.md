# fixtures

The consumer matrix installs the registry into three independent shadcn projects and checks the installed components in Chromium.

## Run locally

Start with no uncommitted changes in `fixtures/consumers/`. From the repository root, install dependencies, build the registry and run one style:

```bash
bun install
just build-registry
bash scripts/ci/consumer-matrix.sh radix-nova
```

Repeat with `base-mira` and `base-vega`. Run one style at a time because they share the preview port. To test a fresh project generated by the latest CLI instead of the committed fixture, append `--latest`.

The script installs Chromium. On a fresh Linux machine, first run `bunx playwright install --with-deps chromium` from the repository root to install its system dependencies as well.

The script rewrites tracked fixture files. After the runs, restore those files:

```bash
git restore -- fixtures/consumers
```

## What the matrix checks

`consumers/` holds the three locked styles: `radix-nova`, `base-mira` and `base-vega`. Each starts from `shadcn init -t vite`, reduced to its config, lockfile, stylesheet and empty entry. They are separate projects with their own dependencies, not root workspaces.

The installed `src/components`, `src/lib`, `src/hooks` and `src/smoke` directories are ignored. CI runs `shadcn add` against the built registry, including its built-in dependencies, so the fixtures cannot supply an undeclared dependency from committed component files.

`smoke/` holds a scene for each item, the entry that mounts them and the Playwright spec. The matrix script copies these into the consumer after installation, typechecks, builds and runs the browser checks. Errors in tradecn's installed files or smoke scenes fail the job; errors confined to the consumer's own shadcn files are reported as upstream errors and excluded from that failure count.

## Styles and themes

Tailwind skips ignored files when scanning for classes. The script adds `@source` lines for the installed directories before building, and the first smoke test checks that the grid is clipped to its box and `bg-up` paints a color. Ordinary consumers don't need these fixture-specific lines when their source directories are not ignored.

Themes are excluded from the initial installation because each overwrites the palette. After the plain run, the script installs each theme separately, rebuilds and reruns the full spec. `TRADECN_THEME` enables an additional check that reads the theme values back from the page. Colors are compared through a probe element because production builds can change their text representation.

## Icons

All three fixtures use lucide. The Base UI presets default to Hugeicons, whose 4.3 release imported `Grid2x2XIcon.js` and `Grid3x2Icon.js` while the files were named `Grid2X2XIcon.js` and `Grid3X2Icon.js`. That casing mismatch bundled on macOS but failed on Linux before reaching tradecn code. The fixtures use lucide to keep this unrelated package failure out of the component checks.
